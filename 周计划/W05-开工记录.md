## 三、技术选择：这一版为什么没用 React

计划里 D5 写的是"React 写最小聊天窗"。实际做的是**无构建单页**（原生 HTML/CSS/JS，三个文件），理由：

| 维度 | 无构建单页 | Vite + React |
|---|---|---|
| 从零到能点 | 0 分钟（就是文件）| 装 node_modules、配 vite、可能踩源/版本 |
| 演示环境 | 断网可跑，无 CDN 依赖 | 需要 `npm run dev` 或先 build |
| 改一行看效果 | 刷新即生效 | 有 HMR，但多一层构建 |
| 和 W05 验收的关系 | **直接相关** | 无关（验收看入口通不通）|

**这不是偷懒，是把 W05 的变量减到最少。** W06 做正式 Demo（前端+后台）时再决定要不要上 React/组件库 —— 那时才真的需要它。

> 不同意这个决定就说一声，我把 D5 改回 React；改动只在 `web/` 这一层，下面不动。

## 六、D4 还差的那件事：连续追问（要你做个决定）

现在的问题：每问一次都是独立的，问"它多少钱？"它不知道"它"是谁。

三种做法，成本和效果不一样：

| 方案 | 怎么做 | 代价 | 效果 |
|---|---|---|---|
| A 前端拼历史 | 把最近 2 轮问答拼进 question 一起发 | 5 分钟 | 检索会被历史污染，命中率下降 |
| B 后端会话 + 追问改写 | 会话表存最近 3 轮；把"它多少钱"改写成"X1 基础版多少钱"再检索 | 1~2 小时 | 检索干净，答案连贯；**推荐** |
| C 全量对话塞 Prompt | 不检索，直接把历史给模型 | 20 分钟 | 会脱离知识库瞎答，和企业承诺冲突 |

**推荐 B。** 你回一句"走 B"，我再动手；有别的判断就直说。

## 八、已知问题（别在客户面前夸口）

1. **词频检索不懂同义**：问"产品保修期"只有 0.359 分，靠模型兜住说"没有"。根因和 W04 一致（保修 vs 服务期），向量召回留 W06。
2. **问答记录在内存**：重启即丢。收紧清单第 2 项。
3. **没有流式输出**：现在是"检索中 1.3s"的加载态 + 最终答案。真要流式，`/api/ask` 要换成 `StreamingResponse` + SSE。
4. **没有鉴权/限流**：演示阶段故意放开，上线前必须补。
5. **长度限制**：前端 500 字、后端 Pydantic 500 字，两边都拦。
