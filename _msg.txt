W03D6: LLM Rerank 实验完成（3/3 通过，但有保留）

本人实现 judge() 与 rerank()：
- judge：构造 0-10 评分提示词 + 正则抠数字 + 夹取防越界 + 解析失败返 0
- rerank：收集副本并附分数 -> 统一排序 -> 过滤 -> 截取

修掉的四个问题：
- judge 忘记 return（函数返回 None）
- 误把 list 当 dict 用字符串下标 hits["llm_score"]
- 边打分边排序，导致跳着打分、有的打两遍有的没打
- 低于 min_score 时置 0 而不是真正剔除

关键发现（本次实验最有价值的部分）：
1. 案例 2/3 真解决：rerank 后 LLM=7 vs 3，正确片段升到首位
2. 案例 1 未真解决：加"同义词也算"的提示词后，LLM 仍给 3 分
   -> 提示词调整对语义判断无效，这是结构性缺陷
3. 级联失败链：词频排序错 -> 相对阈值（0.45）砍掉正确答案（0.309）
   -> rerank 连候选都看不到。改 rel_threshold=0 宽召回后案例 2 才救回

结论：
- 宽召回 + 精排是行业标准做法
- 但"同义词"问题提示词治不了，需 embedding（根治）
  或同义词词典 / 查询扩展（短平快，但需人工维护）
