## 一、部署与开发成本（实测）

| 项 | 自研 | Dify 本地部署 |
|---|---|---|
| 从零到能问答 | 约 3 个晚上（含写代码、调参、评测）| **约 2 小时**（下镜像 9.4 GB + 配插件 + 搭流程）|
| 磁盘占用 | < 5 MB | **约 9.4 GB 镜像 + 1.5 GB 数据** |
| 内存占用 | 几乎为 0 | **约 2-4 GB 常驻** |
| 依赖 | 零（标准库）| **Docker + WSL2** |
| 客户能不能自己改 | ❌ 要改代码 | ✅ **界面点几下就行** |
| 出问题怎么查 | 看自己的日志 | 看 6 个容器的日志 + 插件守护进程 |

**结论**：
- **卖给客户 → Dify**（客户能自己维护，你不用当保姆）
- **自己用/做原型 → 自研**（零依赖、可控、快）

## 二、切片对比（同一批 4 份资料）

| | 自研（400 字/重叠80）| Dify 默认 | Dify 调优后 |
|---|---|---|---|
| 分段数 | **8** | **62** | **23** |
| 平均字数 | 204 | **26** | 72 |
| 最短 | —— | **2 字** | 12 字 |
| 效果 | 每段≈一节 | ❌ 每行一段，全是标题 | 每段≈一节 |

**Dify 默认分段标识符是换行（`\n`）**，导致 markdown 的每个标题、每个列表项都单独成段。
**改成双换行（`\n\n`）后，从 62 段降到 23 段**，才达到可用水平。

> **教训**：默认配置不可信，**必须按自己的资料结构调整**。
> 这条和 W03 实验 C 的结论完全一致：切片粒度决定答案完不完整。

| 问题 | 自研 | Dify（经济模式）|
|---|---|---|
| 员工请假怎么申请？ | ✅ 4 步完整 | ✅ 4 步完整，自动带来源 |
| 超过 2000 元退款怎么处理？ | ✅ 答出"1 小时内上报主管" | ❌ 答"没有相关规则" |

### 为什么第 2 题自研赢

正确答案在「客户投诉处理标准流程」这一节里（升级机制第 4 条），
**但这一节的标题里没有"退款"两个字**。

- **自研**：词频 + 长度归一化，把它排到了第 2 名，`top_k=3` 让模型看到了它
- **Dify 经济模式**：捞到「产品资料 · 退款政策」（标题就有"退款"），答成了另一件事

**两者都是字面匹配，但打分细节不同，结果就差了。**

### 为什么第 3 题都输

资料里写的是「软件**服务期**以购买年限为准」，问题问的是「**保修期**」。

**字面不重叠 → 谁都匹配不到。**

## 七、Dify 调自研接口（2026-10-29 打通）

**目标**：让 Dify 不只是"查资料"，还能"查实时数据"。

### 做法

1. 用 FastAPI 写一个工具服务 `项目/kb-api/tool_api.py`，跑在本机 `8200` 端口
   - `GET /api/stock?sku=X1-BASIC` → 库存
   - `GET /api/order?order_id=...` → 订单状态
2. Dify 里加一个 **HTTP 请求** 节点，URL 填 `http://host.docker.internal:8200/api/stock?sku=X1-BASIC`
3. 把 HTTP 节点的返回接到 LLM 的上下文里

### 一个必须知道的坑

Docker 容器默认**出不去**到宿主机（SSRF 防护）。

```
初期报错：连接被拒绝 / 请求超时
原因：Dify 的 ssrf_proxy 拦了内网地址
修复：在 D:\Dify\docker\.env 加
      SSRF_PROXY_ALLOW_PRIVATE_DOMAINS=host.docker.internal
      然后 docker compose up -d --force-recreate ssrf_proxy api
```

### 实测结果

问：「X1 基础版还有库存吗？」

```
有库存。智能客服机器人 X1 基础版当前现货 42 套。
来源：产品资料中的实时库存数据（SKU：X1-BASIC）
```

**42 是 `tool_api.py` 里 `STOCK` 字典的值，不是模型编的。**

### 为什么这一步重要（商业价值）

| 只会查资料 | 会调接口 |
|---|---|
| 答"资料里写的是……" | 答"**现在**还有 42 套" |
| 资料过期就答错 | 实时准确 |
| 只能做 FAQ 客服 | 能做 **查库存、查订单、查工单** 的业务助手 |

> **这一条就是"知识库"和"业务系统"的分界线。**
> 客户愿意为"能查实时数据"付的钱，远多于"能搜文档"。

## 八、实验 G：向量检索能不能救回「保修期」？（2026-10-29 实测）

**问题**：问「产品保修期多久？」，资料里写的是「软件**服务期**以购买年限为准」。

用 `embedding_probe.py` 跑同一套切块（8 段），词频和 bge-m3 向量各排一次名：

| 名次 | 词频法 | 向量法（bge-m3）|
|---|---|---|
| 1 | 产品资料 · 产品概述 **0.359**（无答案）| **保修与售后 0.6638** ★（答案在这）|
| 2 | **保修与售后 0.186** ★（被 0.25 门槛砍掉）| 培训文档 · 高频问题 0.5634（无关）|
| 3 | 其余全部 0 分 | 员工手册 · 年假 0.5626（无关）|
| 4 | | 销售资料 · 异议三 0.5463（无关）|
| 5 | | 产品资料 · 产品概述 0.5406（无答案）|

### 结论一：救回来了 ✅

```
词频: 第 2 名，0.186 → 低于 0.25 门槛，被丢掉，模型根本看不到
向量: 第 1 名，0.6638 → 稳稳进 top-3
```

**"保修期"和"服务期"在向量空间里确实靠近。** 这验证了 embedding 的核心价值。

### 结论二：但噪声同时激增 ⚠️（这条最值钱）

看向量第 2-4 名：**培训文档、员工手册年假、销售话术**——**全是无关内容**。

- 第 2 名「培训文档」的词频分是 **0**，纯靠"语义看起来像"挤进第 2
- 「员工手册 · 年假」**0.5626**，距离正确答案 **0.6638** 只差 0.1，
  距离第 2 名 **0.5634** 只差 **0.0008**

**换句话说：向量法把正确答案捞上来的同时，也把一堆无关内容一起捞上来了。**
不配精排的话，模型很可能拿"年假规定"去回答"保修期多久"。

### 结论三：向量分数没法设门槛 ⚠️

| | 分数分布 | 能不能设阈值 |
|---|---|---|
| 词频法 | 0.186 ~ 0.359，无关的全是 **0** | ✅ 能，0.25 一刀切很干净 |
| 向量法 | 0.5195 ~ 0.6638，**跨度只有 0.14** | ❌ 不能 |

- 门槛设 0.6 → 只剩 1 条，太狠
- 门槛设 0.55 → 4 条全进，包含"年假"

**余弦相似度没有绝对意义**，bge-m3 的分数天然挤在 0.5~0.7 这个区间。
词频法那种"绝对下限 0.25 宁少勿滥"的锚点，在向量法里**不存在**。

### 总结论：不是替换关系，是分工关系

```
词频法：精确但会漏（同义词完全抓不到）
向量法：召回广但噪声大（什么都"像"）
    ↓
正确架构 = 向量宽召回（top-10~20）→ LLM 精排（只留 3 条）
```

> **这就是为什么正经的 RAG 方案都是"两段式检索"，而不是"上了向量就完事"。**
> 只上向量不配 rerank，客户会问你："为什么它拿年假制度回答我保修期？"

## 八之二、实验 G-2：加上 LLM 精排（2026-10-29 实测）

对向量 top-6 的候选，用 W03 写的 `judge()`（0-10 分）逐段打分：

| LLM 分 | 片段 | 是否含答案 |
|---|---|---|
| **3** | 产品资料 · 保修与售后 | ✅ **含答案** |
| 0 | 员工手册 · 考勤与请假 | ✗ |
| 0 | 产品资料 · 产品概述 | ✗ |
| 0 | 销售资料 · 常见异议应对 | ✗ |

### 结论一：区分度完美，噪声清零 ✅

无关的全是 **0 分**，含答案的是 **3 分**。精排把"年假"彻底踢出局了。

### 结论二：但绝对门槛 5 分会把正确答案一起杀掉 ❌

`rerank(min_score=5)` → 3 分 < 5 分 → **全部被过滤 → 等于拒答**。

**修法：门槛降到 3**（`--rerank-min 3`），或用相对门槛（明显高于其他候选即可）。

### 结论三：这是"每个环节都有自己的偏见"

| 环节 | 擅长 | 自己的毛病 |
|---|---|---|
| 词频 | 精确、可解释、能设绝对门槛 | **漏同义词**（服务期 ≠ 保修期）|
| 向量 | 召回广，救命 | **噪声大**（年假 0.5626 也很像）|
| LLM 精排 | 区分度极好（3 vs 0）| **打分保守**（同义不同词只给 3）|

**精排的价值在"排序"，不在"绝对分数"。**
DeepSeek 对"同义但字面不同"的段落只给 3 分——你非要按"≥5"卡，就把唯一的正确答案扔了。

> **这跟 W03 设计的两道门槛是同一个道理**：
> 「绝对 0.25 + 相对 45%」——精排也必须双门槛，
> 因为模型整体打分偏低时，纯绝对门槛一定误杀。

### 总结论：向量宽召回 + 精排（门槛要调）

```
vec top-6 → 精排打分 → 门前 3 → 得分最高者的原文交给 LLM 生成
```

## 八之三、环境坑：两个 Python 会互相坑（2026-10-29）

```
C:\Python313\python.exe     3.13.1   装了 python-dotenv  → 能读 .env
D:\ANACONDA\python.exe      3.11.4   没装 python-dotenv  → 读不到 Key
```

终端前面带 `(base)` 时用的是 **Anaconda 那个**，于是 `llm.py` 里
`import dotenv` 失败 → 被 `except Exception: pass` 静默吞掉 → 报"没有找到任何可用的模型"。

**修法**：
```powershell
D:\ANACONDA\python.exe -m pip install python-dotenv -i https://mirrors.aliyun.com/pypi/simple/
```
（清华源当时返回 403，阿里源可用）

> **教训**：`try: ... except Exception: pass` 这种写法会让配置错误彻底静默。
> 排查"Key 明明配了却读不到"时，**第一件事是确认当前 `python` 是哪一个**：
> ```powershell
> python -c "import sys; print(sys.executable)"
> ```
