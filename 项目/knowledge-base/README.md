# 企业知识库 Agent（RAG 最小可用版）

Week 3 的学习产物。**零第三方依赖**（不需要 openai / chromadb / langchain），词频检索 + 引用约束，先跑通再升级。

## 实测数字（我建好示例资料后跑出来的）

| 指标 | 结果 |
|---|---|
| 该答的题命中率 | **5/6 = 83%** |
| 不该答的题拒答率 | **4/4 = 100%** |
| 文档 → 切片 | 4 篇 → 8 片（平均 204 字）|
| 相关问题的检索分 | 1.0 ~ 1.4 |
| 无关问题的最高分 | 0.147（被 0.25 门槛拦住）|

> **这两个数字要一起看**：命中率低 = 找不到资料；拒答率低 = 敢瞎编（更危险，会丢客户）。
> 只汇报命中率的产品经理，都在骗自己。

## 架构

```
文档(data/) → 解析 → 切片(标题层级+重叠+碎片合并) → 建索引(TF-IDF)
                                                          ↓
                          用户提问 ──→ 检索 ──→ 双重门槛过滤 ──→ Top-K 片段
                                                          ↓
                                        Prompt："只能依据资料回答 + 标注来源"
                                                          ↓
                                                答案（带 [来源: 文件-小节]）
                                                          ↓
                                       资料里没有 → 明确拒答（不编造）
```

## 三个设计决策（都是踩出来的）

| 决策 | 为什么 |
|---|---|
| **碎片合并**（`min_block_chars=120`） | 第一版没合并时，切片平均只有 76 字，`## 价格方案` 这种一行标题成了独立切片，检索时纯噪声。合并后 8 片/204 字，命中率明显变好 |
| **两道分数门槛**（绝对 0.25 + 相对 45%） | Top-K 一定会凑满 K 个结果，哪怕全都不相关。实测无关问题最高分 0.147 却仍被当"资料"喂给 LLM —— **把噪声当资料，是 RAG 答错的头号原因** |
| **拒答优先于作答** | 企业客户最怕的不是"答不出"，是"一本正经地胡说"。宁少勿滥是能收钱的那句话 |

## 运行

```powershell
python rag.py --build                                  # 建索引
python rag.py --ask "如何处理客户投诉" --no-llm          # 只看检索，不花钱
python rag.py --ask "如何处理客户投诉"                   # 完整问答（要 API Key）
python rag.py --eval                                   # 跑评测集，出命中率/拒答率
python rag.py --ask "某问题" --min-score 0.5            # 调门槛，看误答怎么变
```

## 已知短板（这就是你 W03 要亲手补的功课）

1. **同义词打不中**：问"保修期多久"，资料里写的是"服务期"，词频匹配失败 → **这就是为什么需要 Embedding 语义检索**。
2. **没有 Rerank**：只按词频排序，没有交叉编码器精排。
3. **没做多轮对话**：每次提问都是孤立的。
4. **权限未隔离**：所有切片一视同仁，真实企业要按部门隔离。
5. **无增量更新**：资料变了要整库重建。
