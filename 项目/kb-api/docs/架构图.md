# 企业知识库 Agent · 架构图（W05 交付物之一）

> 一句话：**用户 → 入口 → 接口 → 检索 → 生成（可关）→ 带来源返回。**
> 用途：W05 交付物；客户面前照着这页讲，30 秒说清系统边界。

## 二、三句话讲给客户

1. **入口不碰业务**：以后要换成企业微信、飞书、钉钉，只换最上面一层，下面一行代码不动。
2. **接口不碰模型**：有额度就用模型组织语言，没额度/断网就返回原文片段 —— 现场演示不会翻车。
3. **检索有闸门**：资料里找不到就明确说找不到。宁可拒答，也不编一个看着像样的答案。

## 三、降级与故障路径（现场救命用）

| 故障 | 系统实际行为 | 演示时怎么说 |
|---|---|---|
| 没配 API Key / 额度用完 | `mode="retrieval"`，返回原文片段 + 来源 | "模型是可选件，资料永远在" |
| 索引没建 | `/api/ask` 返回 503，提示先建索引 | "启动顺序：先建索引，再起服务" |
| 问题为空 / 超 500 字 | 422，前端给中文提示 | "接口层就拦住了，不进模型" |
| 资料里没答案 | `refused=true`，0 条来源 | "这是产品能力，不是故障" |
| 模型 90 秒没回 | 前端超时提示，后端继续跑 | "超时我会告诉你，不会假装在转圈" |
| 后端没起 | 页面顶部红标 + 气泡里给命令 | "页面会自己说它连不上" |

## 四、一次问答的 6 步（对应代码位置）

| 步 | 发生什么 | 在哪 |
|---|---|---|
| 1 | 用户输入，Enter 提交 | `web/app.js` → `ask()` |
| 2 | POST `/api/ask`，前端 90s 超时兜底 | `web/app.js` |
| 3 | Pydantic 校验字段范围 | `server.py` → `AskRequest` |
| 4 | 检索 + 双闸门过滤 | `rag.py` → `search()` |
| 5 | 无命中 → 拒答；有命中 → 组 Prompt 调模型 | `server.py` → `do_rag()` / `rag.py` → `answer()` |
| 6 | 返回 answer + sources + mode，页面渲染 | `server.py` → `ask()` |

## 五、和 Dify 路线的关系

- **Dify 路线**（W04 已跑通）：Docker 12 容器，2 小时装好，4-9 GB 内存，适合"客户要可视化后台自己改"。
- **自研路线**（本图）：一个 Python 文件 + 一个 HTML 页面，几十 MB，适合"轻、快、成本可控"。
- 两条路线共用同一个 `do_rag()` 思路和同一份资料 —— 这才是能换着交付的底气。
  详细对照见 `项目/knowledge-base/自研-vs-Dify-对照表.md`。
