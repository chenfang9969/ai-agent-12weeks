## 接口清单

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/` | **网页聊天窗**（W05 入口，静态页）|
| GET | `/api` | 接口清单 JSON |
| GET | `/api/health` | 健康检查 + 当前模式（`llm` / `retrieval`）|
| POST | `/api/ask` | **核心接口**，所有入口都调它 |
| GET | `/api/documents` | 文档清单（后台管理页用）|
| POST | `/api/reindex` | 资料更新后一键重建索引 |
| GET | `/api/logs` | 问答记录（客户最想看"用户都问了什么"）|
| GET | `/docs` | FastAPI 自动文档，**可直接演示给客户看** |

## 一个重要的设计决策

> **没有 API Key 也能跑。** 没有 LLM 时自动降级为"检索模式"：仍返回原文片段 + 来源，
> 只是不做自然语言总结。

为什么这个设计值钱：
1. **现场演示不会翻车** —— 客户会议室网络差、额度用完，Demo 照样能演
2. **成本可控** —— 内部测试阶段不烧钱
3. **诚实** —— 接口明确告诉你当前是哪种模式，不假装

## 入口层怎么写的（W05）

```
web/index.html   骨架：欢迎语 + 4 条演示问题 + 输入区
web/styles.css   样式：无外网依赖（断网也好看）
web/app.js       提问 / 渲染 / 来源折叠 / 90s 超时 / 健康检查
```

三个文件的全部工作就是 `fetch('/api/ask')` + 画出来。**业务逻辑一行都没有** ——
换成企业微信/飞书时，这一层整个替换，`do_rag()` 不动。
